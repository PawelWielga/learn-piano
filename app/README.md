# Learn Piano Web

Web-only Flutter application for the first MVP. The microphone tester now shows live pitch candidates (note and octave), frequency, confidence, audio level, sample rate and PCM buffer size. Stable NoteOn/NoteOff events now derive from successive pitch estimates; MIDI import now reads local SMF type 0/1 files; melody selection validates one track/channel for single-note practice; physical keyboard range validation now prevents unplayable melody selection; the physical keyboard preview now renders key geometry and highlights (#11); the stationary falling-note preview now covers #12; a deterministic Wait for Note core now covers #13; the microphone-connected training screen now completes #14.

## Prerequisites

- Flutter **3.47.7** (stable; Dart 3.13.5)
- Chrome for local web development
- Node.js 22 for the JavaScript bridge tests

## Run

```sh
cd app
flutter pub get
flutter run -d chrome
```

## Validate and build

```sh
cd app
dart format --output=none --set-exit-if-changed .
flutter analyze
flutter test
node --test test_js/*.test.cjs
flutter build web --release --base-href /learn-piano/
```

The build outputs `app/build/web`. The base href must match the GitHub Pages repository subpath. Don't commit generated `build/` files. The browser bootstrap script is generated by Flutter during the build.

The dependency versions are pinned in `pubspec.lock`, generated with Flutter 3.47.7. After changing `pubspec.yaml`, run `flutter pub get` and review the lockfile diff.

## Import MIDI z urządzenia (#8)

Na ekranie głównym kliknij **Importuj plik MIDI** i wybierz lokalny plik `.mid` lub `.midi`. Wyświetlą się typ pliku, PPQ, czas utworu, liczba nut, zmiany tempa, nazwy ścieżek i podgląd pierwszych nut. Po imporcie wybierasz pojedynczą partię jednogłosową (ścieżka i kanał), a aplikacja ostrzega o akordach. Możesz ustawić zakres fizycznej klawiatury i sprawdzić, czy wybrane nuty da się zagrać; klawiaturę i trening uruchamiasz po wybraniu partii zgodnej z zakresem.

- `lib/src/midi/midi_parser.dart` to czysty Dart bez dodatkowych bibliotek. Obsługuje nagłówki SMF typu 0 i 1, wiele ścieżek i kanałów, delta ticks i PPQ, globalne zmiany tempa, running status, SysEx, meta events, nuty NoteOn/NoteOff (także NoteOn velocity=0), długości nut i pauzy.
- `web/midi_file_input.js` otwiera systemowe okno wyboru, odczytuje `File.arrayBuffer()` i przekazuje bajty do Darta przez JS interop. Dane nie są wysyłane ani zapisywane, nie używamy backendu ani analityki.
- Ograniczenia: pliki **do 2 MB**, **do 64 ścieżek**, wyłącznie **PPQ**. Typ 2, SMPTE, uszkodzone i niedomknięte zdarzenia NoteOn dają kontrolowany błąd. NoteOff bez NoteOn jest pomijany; nakładające się identyczne nuty na jednym kanale łączone są FIFO.
- Globalna oś tempa korzysta domyślnie z 120 BPM (500 000 mikrosekund na ćwierćnutę), dopóki plik nie ustawi nowego tempa. Dla jednakowego ticka ostatnie zdarzenie tempa w ustalonej kolejności ścieżka/zdarzenie wygrywa. W czasie nuty uwzględniane są zmiany tempa.
- Testy generują niewielkie, własne fixtury SMF typu 0/1 (bez komercyjnych melodii). Sprawdzają pauzy, tempo między ścieżkami, nakładanie nut, running status i uszkodzone nagłówki; testy widgetowe działają z fake pickerem, a Node sprawdza mostek wyboru pliku.

## Wybór partii i walidacja monofoniczności (#9)

Po wczytaniu MIDI aplikacja dzieli każdą ścieżkę na osobne kanały MIDI, również w plikach typu 0. Nie łączy kanałów i nie wybiera automatycznie melodii. Przy każdej partii pokazuje liczbę nut, zakres, czas oraz status. Kliknięcie dostępnej partii zapisuje w pamięci bieżącego ekranu `MelodySelection` z uporządkowaną, niemodyfikowalną listą `MidiNote` dla przyszłego treningu. Zmiana pliku czyści poprzedni wybór.

- **Jednogłosowość:** dwa `NoteOn` o identycznym ticku albo początek kolejnej nuty wcześniejszy niż koniec poprzedniej oznaczają nakładanie się nut. Dotyczy to również powtórzonego tego samego dźwięku. Dokładnie stykające się nuty i pauzy są dozwolone.
- **Akordy/polifonia:** status z liczbą wykrytych nakładających się nut i brak możliwości wyboru. Nie próbujemy wyciągać pojedynczego głosu z akordu.
- **Perkusja:** kanał 10 MIDI (indeks 9) jest pokazany jako nieobsługiwany. Ścieżki bez nut są prezentowane jako puste i nie można ich wybrać.
- **Granica etapu:** wybór partii nie uruchamia mikrofonu ani treningu. W #10 można skonfigurować zakres fizycznej klawiatury i zobaczyć liczbę nut poza zakresem. Klawiatura graficzna i trening pozostają etapami #11–#14.

Deterministyczne testy walidatora obejmują wiele ścieżek, typ 0 z kilkoma kanałami, puste partie, perkusję, identyczne początki, powtarzane dźwięki, nakładanie i pauzy. Testy widgetowe obejmują wybór, blokadę akordów i zmianę pliku.

## Zakres fizycznej klawiatury (#10)

Wybierz **Ustaw zakres klawiatury** na ekranie głównym lub **Dostosuj klawiaturę** po wybraniu melodii MIDI. Możesz wybrać typowe zakresy 37 (C3–C6), 49 (C3–C7), 61 (C2–C7) albo 88 (A0–C8) klawiszy, a także zmienić samodzielnie najniższą i najwyższą nutę (MIDI 0–127) poprzez wybór nuty lub przyciski ± półton. **Domyślny zakres to 61 klawiszy C2–C7**; jest to tylko ustawienie startowe, nie detekcja modelu instrumentu.

`lib/src/instrument/instrument_range.dart` jest pojedynczym modelem zakresu dla walidatora melodii, przyszłej klawiatury graficznej (#11) i silnika treningu (#13). Obie granice są **włącznie**. `checkNotes` liczy każde wystąpienie nuty spoza zakresu (także powtórzenia) i pokazuje przykładowe unikatowe wysokości. Partia zawierająca choć jedną niedostępną nutę nie jest gotowa do ćwiczenia. MIDI nie jest transponowane ani przycinane. Po zmianie ustawień status wybranej melodii jest ponownie wyliczany.

Preferencja `v1:LOW:HIGH` jest zapisywana **wyłącznie w przeglądarce** przez `web/instrument_range.js` i `localStorage`. Nie zapisujemy plików MIDI ani dźwięku. Uszkodzona wartość jest ignorowana; niedostępne localStorage nie blokuje importu, a ekran ustawień pozwala użyć zakresu w aktualnej sesji bez trwałego zapisu. Android/iOS nie używają tego adaptera w MVP Web.

Testy obejmują granice 0/127, wartości niepoprawne, presety, powtarzane nuty poza zakresem, błędy zapisu, integrację z wyborem MIDI i lokalną warstwę JS. **Pełna wizualizacja klawiatury jest w #11**: w #10 pokazujemy tylko wartości i zgodność partii, bez grafiki klawiszy. Brak możliwości rozpoczęcia treningu jest zachowany, ponieważ tryb ćwiczenia jeszcze nie istnieje.

## Podgląd spadających nut (#12)

Po zaimportowaniu MIDI i wybraniu jednogłosowej partii, której wszystkie nuty mieszczą się w ustawionym zakresie, ekran pokazuje **oś czasu z blokami nad fizycznymi klawiszami**. Kolor zielony oznacza aktualną nutę, niebieskie bloki to przyszłe nuty, a pozioma linia oznacza moment rozpoczęcia bieżącej nuty. Długości bloków i odstępy między nimi wynikają z bezwzględnych czasów startu i długości wyliczonych z mapy tempa MIDI. Nuty o zerowym czasie trwania mają minimalny widoczny znacznik (4 px). Klawiatura i bloki używają dokładnie tych samych współrzędnych X, także przy niepełnych oktawach. Cały podgląd przewija się w poziomie na telefonie i desktopie.

Przyciski **Poprzednia** i **Następna** przesuwają tylko numer oczekiwanej nuty. Nie jest używany zegar odtwarzania, timer ani mikrofon; podgląd stoi w miejscu, dopóki nie wybierzesz kolejnej nuty. Widok został przygotowany pod przekazywanie indeksu z silnika *Wait for Note* (#13); to nie jest jeszcze właściwe ćwiczenie. Po wyborze innej partii lub nowego pliku pozycja wraca do początku.

Oś czasu ma maksymalną skalę 88 px/s, ale przy długich pauzach pomniejsza ją na podstawie pięciu kolejnych początków nut, żeby były widoczne. Jedna skala obowiązuje zarówno przesunięcia, jak i długości bloków. Dla bardzo długich nut górna część może być ucięta w oknie podglądu. Renderer tworzy figury tylko dla nut, które przecinają bieżące okno czasu, zamiast rysować cały długi utwór. Jeśli wybrana melodia wykracza poza fizyczny zakres, użytkownik widzi ostrzeżenie i klawiaturę zamiast częściowo pominiętych bloków.

Testy: `test/midi/falling_notes_view_test.dart` sprawdza mapowanie czasu/długości/pauz i osi X, dopasowywanie skali, zerowe długości, przewijanie oraz culling przy długich utworach; `test/midi/falling_notes_import_test.dart` sprawdza zmiany pozycji po zaimportowaniu melodii. Testy automatyczne nie zastępują ręcznego sprawdzenia płynności w przeglądarce mobilnej.

## Silnik ćwiczenia „Wait for Note” (#13)

`lib/src/training/wait_for_note_engine.dart` to niezależny od Fluttera, mikrofonu i zegara automat stanu. Konstruktor przyjmuje `MelodySelection` z jednogłosowej partii oraz obowiązujący `InstrumentRange`. Nieprawidłowa, pusta, perkusyjna, wielogłosowa lub niegrywalna melodia daje stan `error` z komunikatem, zamiast startu niemożliwego ćwiczenia.

Stany: `ready` → `running` ↔ `paused` → `completed` oraz `error` dla niepoprawnego wejścia. Dostępne są `start()`, `pause()`, `resume()`, `reset()` i `onNoteEvent(NoteEvent)`. Silnik przyjmuje **wyłącznie stabilne zdarzenia NoteOn/NoteOff** ze strumienia `NoteEventTracker`, nie chwilowe kandydaty częstotliwości ani same dane PCM. Każdy poprawny NoteOn przesuwa indeks o **jedną** nutę MIDI (łącznie z oktawą), błędny NoteOn go nie zmienia. Wynik pojedynczego zdarzenia jest rozróżniony jako `correct`, `incorrect` lub `ignored`. Migotanie, cisza i `NoteOff` nie zaliczają kroków. Pauzy z pliku MIDI nie opóźniają ćwiczenia, a widok w #12 może pobierać `snapshot.currentIndex` i `snapshot.expectedMidiNote` bez osobnego zegara.

Silnik śledzi aktualnie brzmiące wysokości. Drugie `NoteOn` bez `NoteOff` tej samej wysokości **nie zalicza** kolejnej nuty, nawet przy zdublowanych komunikatach. Zdarzenia trafiające do silnika podczas pauzy i przed startem nie dają punktów, ale wciąż aktualizują informację o trzymanych klawiszach. Reset czyści progres, lecz zachowuje tę informację: aby po resecie zagrać ten sam dźwięk, trzeba go najpierw zwolnić. Po ukończeniu utworu nie ma następnej oczekiwanej nuty i nowy start wymaga resetu.

**Ekran treningu (#14):** po imporcie MIDI wybierz jednogłosową partię bez nut poza zakresem instrumentu i przycisk **Rozpocznij trening**. Przycisk **Start i mikrofon** uruchamia przetwarzanie dopiero po akcji użytkownika. Wycisz pianino na chwilę: ekran musi zaobserwować 240 ms ciągłej ciszy w analizowanych klatkach, zanim zacznie zaliczać uderzenia. Zapobiega to zaliczeniu wybrzmiewającego dźwięku po uruchomieniu/wznowieniu. Zdarzenia NoteOn/NoteOff z trackera trafiają do silnika, a postęp, aktualna nuta i spadające bloki są odświeżane z jednego `TrainingSnapshot`. Klawiatura pokazuje oczekiwany i wykryty klawisz. Błędny NoteOn daje komunikat bez przesunięcia melodii; po ostatniej poprawnej nucie widać ekran ukończenia.

**Pauza / Wznów / Reset / Zmień utwór:** pauza zatrzymuje strumień mikrofonu i zapamiętuje indeks. Wznowienie ponownie prosi o strumień i czeka na potwierdzoną ciszę; dopiero wówczas silnik usuwa zapamiętane brzmienia z poprzedniej sesji. Reset cofa postęp i wyłącza mikrofon. Ukończenie i opuszczenie ekranu również zwalniają strumień. Odmowa uprawnień i zerwanie nasłuchu pokazują błąd i pozwalają ponowić próbę. Strona nie wysyła nagrań ani MIDI na serwer. Testy `test/training/training_screen_test.dart` korzystają z syntetycznego PCM i nie wymagają mikrofonu na CI. Testy manualne na urządzeniach pozostają otwarte w #7/#16.

**Ograniczenie fizyczne:** mikrofon nie pozwala niezawodnie rozpoznać ponownego uderzenia tej samej wysokości bez słyszalnej przerwy; silnik nie zgaduje takich uderzeń.

Testy `test/training/wait_for_note_engine_test.dart` obejmują poprawne i błędne nuty/oktawy, C4-C4-C4, pauzę i wznowienie, reset w trakcie trzymania klawisza, koniec utworu i błędne partie. `test/training/wait_for_note_pipeline_test.dart` łączy prawdziwe fixtury MIDI z selektorem partii, trackerem pitch i silnikiem przy deterministycznej sekwencji nut.

## Pozioma orientacja ekranu (#33)

niż szerszych zasłania interfejs komunikatem o obróceniu urządzenia, wyłącza

orientacji w `widget_test.dart` oraz `training/training_screen_test.dart`.

## Browser microphone capture (#4)

The input is requested **only** after tapping **Włącz mikrofon**. The browser requires HTTPS (GitHub Pages) or localhost. `web/audio_input.js` wraps `getUserMedia` and Web Audio. `web/audio_capture_processor.js` buffers mono float PCM on an AudioWorklet thread and transfers 2048-sample frames into Dart through `dart:js_interop`. Frames carry the **actual AudioContext sample rate** and a timestamp relative to its clock. Raw frames stay in the browser, are never saved, uploaded or logged.

- Tapping **Wyłącz mikrofon**, leaving the screen or moving the tab to the background stops tracks and closes the AudioContext.
- Denied permission, missing device, unsupported API and interruption show a message and allow manual retry.
- PCM frames are forwarded at ~23 frames/s at 48 kHz, and UI updates are throttled to at most ~8 times/s.
- Pitch estimates are stabilized into separate NoteOn events (#6) for monophonic input, but do not identify chords. Android/iOS native adapters are outside MVP 1.
- AudioWorklet is preferred to deprecated ScriptProcessorNode. Some embedded/in-app browsers may not support it; no silent fallback to insecure capture is provided.
- Sample timestamps describe AudioContext time, not wall-clock milliseconds. The source is mono (first input channel), without applying an extra gain or compressor. The browser may still apply device or driver processing.

## Live pitch candidates (#5)

`lib/src/pitch/pitch_detector.dart` implements a pure-Dart **YIN** estimator based on cumulative mean normalized difference, selecting the **first** reliable periodicity dip (rather than the strongest FFT peak). Quadratic interpolation estimates periods between samples. Detected pitch is mapped to the nearest MIDI number with **A4 = 440 Hz** and **MIDI 60 = C4**. The visible note is a *raw candidate*, not a stable event or a claim that a piano key was pressed.

Defaults (all configurable in the constructor):

| Setting | Value | Why |
| --- | --- | --- |
| Mono analysis buffer | 2048 float samples | About 42.7 ms at 48 kHz or 46.4 ms at 44.1 kHz |
| Supported frequency | 60–1500 Hz | Covers C2 (65.4 Hz) through C6, with detuning margin; lower frequencies remain unsupported |
| Minimum RMS | 0.015 | Suppress silence and faint ambient sound |
| YIN dip threshold | 0.18 | Search for a clear periodicity |
| Minimum confidence | 0.94 | Reject ambiguous/noisy candidates; may need tuning on a real instrument |
| UI + analysis rate | ≤ roughly 8 times/s | Analyze at most one received frame per 120 ms, rather than every buffer |

**Low-key fix (#27):** A previous 90 Hz cutoff rejected C2–F2 outright and caused the first reliably detected note to be F#2. The new default is 60 Hz. Deterministic tests verify C2, C#2, D2, D#2, E2 and F2 at 44.1/48 kHz, including harmonic-rich synthetic piano tones, without enlarging the 2048-sample buffer or changing analysis rate. YIN also rejects a candidate at the last tested lag (which cannot be confirmed as a local minimum), and slightly tightens the minimum confidence to 0.94 to preserve rejection of two competing notes. This is a software-range correction, **not proof** that every phone microphone captures bass fundamentals accurately. On an actual C2–C6 instrument, check the raw and stable candidates in the microphone tester for each low note. If low notes are still missed or recognized one octave too high, record the microphone model, sample rate, input level and the frequency/confidence shown. Smartphone microphone and driver processing may suppress low frequencies; we may need an adaptive buffer or a different low-frequency strategy after measurements.

The AudioWorklet keeps producing PCM while the Dart UI is throttled. On a mobile device the worst perceived update delay includes the worklet buffer duration and sampling/throttle interval; no end-to-end latency measurement has been performed. `PitchDetector` rejects short/invalid buffers, silence, noise and insufficient periodicity by returning null. It uses the **actual** Web Audio sample rate (not a hard-coded 44.1/48 kHz).

Tests use generated sine waves and tones with harmonics at 44.1/48 kHz across several octaves, plus silence, random noise, invalid frames and closely competing pitches. **No acoustic detector is guaranteed to distinguish all chords, reverb, subharmonics or background music**; an overtone-only sound may cause an octave mistake. Actual piano timbre, attack latency, mobile performance and release/rearticulation must be measured on physical hardware before proceeding past M1.

Try the public tester on Pages: choose **Test mikrofonu**, allow access, play isolated C4 (261.6 Hz) and A4 (440 Hz), then verify the shown MIDI octave, frequency and confidence. Repeat notes, try quieter tones and log missed/incorrect detections under issues #5 and #7. The next manual step (#7) validates stabilizing thresholds and repeated strikes on a real piano.

## Stable NoteOn/NoteOff events (#6)

`lib/src/pitch/note_event_tracker.dart` consumes **throttled YIN results** with AudioContext timestamps and maintains `silent`, `candidate`, `stable` and `releasing` states. It is pure Dart, without Flutter or microphone dependencies. The microphone tester shows the latest raw candidate, the stable note, a phase label, the total number of confirmed **NoteOn** events and the most recent strike. This helps validate consecutive repetitions on real hardware.

| Setting | Default | Meaning |
| --- | --- | --- |
| Minimum stable pitch | 200 ms | Same MIDI note must remain credible over this period before a NoteOn |
| Minimum silence to release | 240 ms | Short missing/ambiguous frames do not end a held note |
| Maximum observation gap | 400 ms | Discard pending candidate/release if analyzed frames pause longer; do not fabricate an onset |
| Minimum confidence | 0.93 | Reject uncertain YIN candidates |
| Maximum tuning deviation | ±35 cents | Reject estimates close to a semitone boundary |

A stable change from one MIDI note to another emits NoteOff for the previous note and NoteOn for the new one. A short wrong-semitone candidate does not switch the held note. **A held note never emits a second NoteOn**. Repeating C4 requires a sufficiently long low-energy gap followed by renewed stable C4 detection. The tracker resets on stop, interruption and the next start; counts reset at the next start.

**Physical limitation:** a piano string rings long after a key is released. No reliable key-up or second strike can be inferred from pitch alone when sound never drops below the silence gate, and reverb/background noise may prevent NoteOff. The current MVP intentionally does **not** guess same-pitch re-articulation from a transient increase in loudness. Test both detached and legato repeated notes on a real keyboard; tune the duration/RMS thresholds based on measured misses and false triggers. A short flutter in pitch or microphone processing can also extend release detection. A 200 ms stability gate plus the ~120 ms frame-analysis interval trades response speed for fewer false events. Actual acoustic latency is not yet measured.

Deterministic unit tests cover repeated strikes, continuous sustain, semitone flicker, brief silence, alternative pitches, threshold rejection, gaps, stale timestamps and resets. Widget tests use fake PCM and verify the counter without needing microphone access on CI. These tests are not a substitute for issue #7's physical keyboard experiments.

## Wirtualna klawiatura (#11)

W ustawieniach zakresu widać na bieżąco rzeczywisty układ klawiszy od najniższej do najwyższej wybranej nuty. Po wyborze jednogłosowej partii MIDI podświetlona jest **pierwsza nuta melodii** (tylko podgląd, jeszcze nie trening). Tester mikrofonu podświetla **stabilną** nutę, a nie surowego kandydata; mikrofon nadal uruchamia się wyłącznie po kliknięciu przycisku.

- Zielono-turkusowy oznacza nutę oczekiwaną, pomarańczowy wykrytą. Jeśli obie są takie same, klawisz jest dwukolorowy. Nazwy nut są dostępne nad klawiaturą; oznaczenia C i klawiszy skrajnych widnieją też na białych klawiszach.
- Wąskie ekrany przewijają się **poziomo**. Początkowy widok ustawia się wokół aktywnej nuty (najpierw oczekiwanej, w przeciwnym razie wykrytej). Zmiana nuty ustawia podgląd ponownie; inne odświeżenia nie odbierają użytkownikowi przewinięcia.
- Układ jest liczony bezpośrednio z `InstrumentRange` oraz numerów MIDI. Fragmenty zaczynające/kończące się na czarnym klawiszu nie są zastępowane pełną oktawą; żaden dźwięk poza ustawionym zakresem nie jest po cichu pokazywany jako dostępny.
- Grafika korzysta z `CustomPainter`, który maluje klawisze w kolejności białe → czarne. Przerysowanie zależy od zakresu lub oznaczonych nut, a tester ogranicza częstotliwość aktualizacji wyników audio (obecnie około 8 FPS).
- Testy jednostkowe sprawdzają geometrię pełnej oktawy, częściowy zakres czarnych klawiszy i pojedynczy klawisz. Widget testy sprawdzają oba oznaczenia oraz przewijanie do aktywnej nuty.

Klawiatura nie odtwarza dźwięków. Spadające nuty i przechodzenie do kolejnej nuty MIDI należą do #12–#14. Nie przeprowadzono jeszcze ręcznych pomiarów wydajności i rozpoznawania na wszystkich przeglądarkach mobilnych.
