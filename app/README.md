# Learn Piano Web

Web-only Flutter application for the first MVP. The home screen opens a microphone test showing capture status, level, actual sample rate and PCM buffer size. Pitch detection, MIDI import and training are separate follow-up issues.

## Prerequisites

- Flutter **3.47.7** (stable; Dart 3.13.5)
- Chrome for local web development
- Node.js 22 for the JavaScript bridge tests

## Run

```sh
cd app
flutter pub get
flutter run -d chrome
```

## Validate and build

```sh
cd app
dart format --output=none --set-exit-if-changed .
flutter analyze
flutter test
node --test test_js/*.test.cjs
flutter build web --release --base-href /learn-piano/
```

The build outputs `app/build/web`. The base href must match the GitHub Pages repository subpath. Don't commit generated `build/` files. The browser bootstrap script is generated by Flutter during the build.

The dependency versions are pinned in `pubspec.lock`, generated with Flutter 3.47.7. After changing `pubspec.yaml`, run `flutter pub get` and review the lockfile diff.

## Browser microphone capture (#4)

The input is requested **only** after tapping **Włącz mikrofon**. The browser requires HTTPS (GitHub Pages) or localhost. `web/audio_input.js` wraps `getUserMedia` and Web Audio. `web/audio_capture_processor.js` buffers mono float PCM on an AudioWorklet thread and transfers 2048-sample frames into Dart through `dart:js_interop`. Frames carry the **actual AudioContext sample rate** and a timestamp relative to its clock. Raw frames stay in the browser, are never saved, uploaded or logged.

- Tapping **Wyłącz mikrofon**, leaving the screen or moving the tab to the background stops tracks and closes the AudioContext.
- Denied permission, missing device, unsupported API and interruption show a message and allow manual retry.
- PCM frames are forwarded at ~23 frames/s at 48 kHz, and UI updates are throttled to at most ~8 times/s.
- There is **no pitch detection yet**; the meter only confirms that audio reaches Flutter. Android/iOS adapters are outside MVP 1.
- AudioWorklet is preferred to deprecated ScriptProcessorNode. Some embedded/in-app browsers may not support it; no silent fallback to insecure capture is provided.
- Sample timestamps describe AudioContext time, not wall-clock milliseconds. The source is mono (first input channel), without applying an extra gain or compressor. The browser may still apply device or driver processing.

### Manual device validation required before closing #4

| Platform | Steps | Result |
| --- | --- | --- |
| Chrome desktop | Open localhost/Pages, allow permission, play note, stop, repeat | Not tested on physical device |
| Chrome Android | Allow, deny, retry, hide tab, unplug mic if possible | Not tested |
| Safari iOS | Open Pages in Safari, grant access, background/foreground, stop | Not tested |

CI covers fake audio UI scenarios and bridge lifecycle through Node mocks, **not** real browser permissions or physical keyboard behavior. On each device check that the OS/browser microphone indicator turns off after stopping. Record actual browser version, phone/OS and failures in issue #4.
